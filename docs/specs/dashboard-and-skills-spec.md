## 3. Configurable Widget Grid — functional spec

### 3.1 User behavior
1. Below the fixed panels, show a responsive grid (4 columns desktop, 2 tablet, 1 mobile).
2. Grid always ends with at least one empty **plus tile** (dashed border, centered `+`, label "Add metric").
3. Click plus → modal opens:
   - Step 1: choose **Platform** (Google Ads, Meta, LSA, GBP, Calls, CRM, Calculated). Only connected platforms are enabled; others show "Connect".
   - Step 2: searchable list of metrics from the catalog filtered to that platform. Show name, short description, format.
   - Step 3 (optional): choose **card type** — Number, Number + sparkline, Line chart, Bar by campaign, Table top-N. Default = Number + sparkline.
   - Step 4 (optional): filter scope — all accounts / one account / one campaign.
   - Confirm → card renders in place of the plus tile; a new plus tile appears after it.
4. Each card has a hover/tap menu: **Rename · Change chart type · Resize (1x1, 2x1, 2x2) · Delete**.
5. Cards are **drag-to-reorder**. Persist order, size, and config per user.
6. "Reset to default" button restores the default set from config without touching the fixed panels above.

### 3.2 Data model
```
DashboardLayout {
  id, user_id, name ("My Dashboard"), is_default bool,
  widgets: Widget[], created_at, updated_at
}
Widget {
  id, layout_id, position int, size enum(1x1,2x1,2x2),
  metric_key string   -- FK to MetricCatalog.key
  card_type enum(number, number_spark, line, bar_by_campaign, table_top_n)
  scope { account_ids[], campaign_ids[] } nullable
  custom_label string nullable
}
```
Store as JSON in Postgres (or existing DB). Migrations only add tables; never alter existing ones.

### 3.3 Rendering
- Every widget calls one function: `getMetric(metric_key, date_range, scope) → { value, prior_value, series[] }`. This function resolves the catalog entry, calls the right connector, applies aggregation, computes delta.
- Calculated metrics resolve their dependencies recursively.
- If a connector is disconnected, card renders in disabled state with "Connect Google Ads" CTA. Never show fake numbers as real; sample mode must be visibly labeled.

## 4. Metric Catalog

### 4.1 Schema (one JSON/YAML file: `config/metric-catalog.json`)
```
{
  "key": "google_ads.impressions",         // unique, dot-namespaced
  "platform": "google_ads",                // google_ads | meta | lsa | gbp | calls | crm | calculated
  "label": "Impressions",
  "description": "Times an ad was shown",
  "api_field": "metrics.impressions",      // exact field name in the source API/report
  "unit": "count",                         // count | currency | percent | seconds | ratio
  "format": "integer",                     // integer | currency | percent_1dp | decimal_2dp | duration
  "aggregation": "sum",                    // sum | avg | last | weighted_avg | recompute
  "direction": "up_good",                  // up_good | down_good | neutral (controls delta color)
  "supports": ["account","campaign","adgroup","ad"],
  "formula": null,                         // for calculated: expression over other keys
  "depends_on": [],                        // for calculated
  "default_card": "number_spark",
  "tags": ["volume","top_of_funnel"]
}
```
Rules:
- Ratios and rates use `aggregation: recompute` (recompute from summed numerator/denominator across the date range; never average the daily rate).
- Currency metrics store account currency; display in user currency.
- Every metric must be testable: include a `sample_value` field used in sample mode.

### 4.2 Full catalog to load (build these entries)

**Google Ads (`google_ads.*`)** — Impressions, Clicks, CTR, Average CPC, Cost, Conversions, Conversion Rate, Cost per Conversion, Conversion Value, ROAS (value/cost), All Conversions, Phone Calls (call asset), Call Impressions, Search Impression Share, Search Lost IS (budget), Search Lost IS (rank), Absolute Top IS, Top IS, Quality Score (avg, adgroup+ level), Invalid Clicks, Video Views, View Rate, Engagements, Interaction Rate, Average CPM, Search Terms count, Optimization Score.

**Google Local Services Ads (`lsa.*`)** — Leads (total), Phone Leads, Message Leads, Booked Leads, Charged Leads, Disputed Leads, Cost per Lead, Total Spend, Lead Response Time (avg), Missed Calls, Rating, Review Count, Ad Impressions (where available), Budget Utilization %.

**Google Business Profile (`gbp.*`)** — Profile Views (Search), Profile Views (Maps), Website Clicks, Direction Requests, Phone Calls, Messages, Bookings, Photo Views, Total Reviews, Average Rating, New Reviews (period), Search Queries count.

**Meta Ads (`meta.*`)** — Impressions, Reach, Frequency, Clicks (all), Link Clicks, CTR (all), CTR (link), CPC (link), CPM, Amount Spent, Results, Cost per Result, Leads (on-Facebook), Cost per Lead, Landing Page Views, Cost per LPV, Messaging Conversations Started, Cost per Conversation, Video Plays (3s), ThruPlays, Video Avg Watch Time, Post Engagement, Purchases / Conversions (pixel), Purchase ROAS, Quality Ranking, Engagement Rate Ranking, Conversion Rate Ranking, Outbound Clicks.

**Calls / Call Tracking (`calls.*`)** — Total Calls, First-Time Callers, Repeat Callers, Answered Calls, Missed Calls, Missed Call Rate, Avg Call Duration, Calls over 60s, Qualified Calls (AI-scored), Booked from Call, Call-to-Booked Rate, Calls by Source, After-Hours Calls, Voicemail count.

**CRM / Job Data (`crm.*`)** — Leads created, Qualified Leads, Estimates Sent, Estimates Won, Booked Jobs, Completed Jobs, Cancelled Jobs, Job Revenue, Avg Ticket, Close Rate (est→won), Lead-to-Book Rate, Speed to Lead (median minutes), Pipeline Value.

**Calculated (`calc.*`)** — Blended Spend (all paid platforms), Blended Leads, Blended CPL, Cost per Qualified Lead, Cost per Booked Job, Cost per Completed Job, Blended ROAS (crm.job_revenue / calc.blended_spend), Marketing % of Revenue, Lead Leak $ (missed calls × answered-call book rate × avg ticket), Budget Pacing % (spend MTD / (monthly budget × day-of-month/days-in-month)), Channel Share of Spend, Channel Share of Booked Jobs.

### 4.3 Formula examples
```
calc.blended_cpl        = calc.blended_spend / calc.blended_leads
calc.cost_per_booked    = calc.blended_spend / crm.booked_jobs
calc.blended_roas       = crm.job_revenue / calc.blended_spend
calc.lead_leak_dollars  = calls.missed_calls * calls.call_to_booked_rate * crm.avg_ticket
calc.budget_pacing_pct  = (calc.blended_spend_mtd / (settings.monthly_budget * (day_of_month / days_in_month))) * 100
```

## 5. The Seven Miles Skills (home services adaptation)

Each skill = one folder: `skills/<name>/SKILL.md` + optional `tools.json` binding. Every SKILL.md follows this template:

```
# <Skill name>
Trigger: <phrases / when Miles should invoke>
Inputs required: <fields Miles must have or ask for>
Reads: <connectors + metric keys>
Writes: <platform actions, or "none — proposal only">
Steps: <numbered>
Output: <exact structure returned to the dashboard/chat>
Approval: <what requires a yes; what is read-only>
Guardrails: <hard limits>
```

| # | B2B original | Miles home-services skill | What it does |
|---|---|---|---|
| 1 | Firmographic audience builder | **Service Area Audience Builder** | Takes ZIPs / radius / cities served, service lines, seasonality profile, and homeowner signals → builds Google location targeting + LSA service areas + Meta geo + interest/behavior stack (homeowners, home improvement, recent movers). Output: audience spec per platform, ready for the launcher. Proposal only. |
| 2 | Intent layer | **Seasonality + Demand Layer** | Reads vertical playbook (HVAC/plumbing/roofing/etc.), Google Trends and search-term data, weather signals if available → recommends which service lines to push this week and budget weighting. Output: weekly demand memo + suggested budget split. Read only. |
| 3 | Campaign launcher | **Campaign Launcher** | Brief in (vertical, service line, offer, budget, geo) → full launch-ready campaign per the spec docs: Google Search RSA (headlines/descriptions/assets), PMax asset group, LSA config checklist, Meta lead campaign (objective, ad set, creative, instant form). Validates every field against character limits. Output: structured campaign object + human preview. Writes only after approval; if no write access, exports JSON + copy-paste sheet. |
| 4 | CPL + funnel reader | **CPL + Funnel Reader** | Weekly readout: spend, leads, qualified, booked, cost per booked, per channel and blended; identifies the leaking stage; flags missed-call leak in dollars. Output: plain-English readout + populates Funnel panel callouts. Read only. |
| 5 | Loser pauser | **Loser Pauser** | Finds campaigns / ad groups / ad sets / keywords with spend above threshold and zero or above-target CPL / cost per booked over lookback window. Proposes pause list with $ saved. Executes pause only on approval; supports one-click revert. |
| 6 | Budget shifter | **Budget Shifter** | Moves daily budget from underperformers to winners across and within platforms, within user-set caps (max % move per day, min budget floor per campaign, monthly ceiling). Proposes; executes on approval. |
| 7 | Channel comparator | **Channel Comparator** | Google Search vs LSA vs PMax vs Meta on cost per qualified lead and cost per booked job for the same service line and geo. Recommends the shift; feeds Placements panel callout. Proposal only; hands off to Budget Shifter for execution. |

### 5.1 Shared guardrails (put in every SKILL.md)
- Never change campaign objective, conversion actions, or billing.
- Never move more than the user's configured daily % cap or below floor.
- Every proposal shows: what changes, why (metrics cited), $ impact, and a revert path.
- Log every run to `skill_runs` table: skill, inputs, outputs, status, approver, timestamp.
- Respect Special Ad Category on Meta for any financing/credit offer.

## 6. Connector abstraction

Build one interface so skills and widgets never talk to platform SDKs directly:
```
Connector {
  platform, status(connected|disconnected|read_only|read_write),
  getMetrics(metric_keys[], date_range, scope),
  listEntities(level),            // accounts, campaigns, ad groups, ads
  proposeAction(action) → preview,
  executeAction(action, approval_id)  // throws if status != read_write
}
```
Implement Google Ads and Meta first (LSA and GBP via Google APIs next; calls/CRM via existing Miles connectors). Until write scopes are granted, all connectors report `read_only` and every skill runs in proposal mode automatically.
